# Mini Player Coupling Contract

This document is the **explicit list of every assumption** this companion makes
about [vdesabou/alfred-spotify-mini-player](https://github.com/vdesabou/alfred-spotify-mini-player).
Each entry is a coupling point: a place where a future mini player release
could change behaviour and break this companion. Diff this file against the
mini player's source on each upgrade.

Last verified: mini player Alfred workflow UUID
`04AB736B-1DB3-42D5-99D5-3B9D2198088A` (UUID is per-install — yours will
differ; see "Path discovery" below).

---

## 1. Paths

| What | Path | Mode |
|------|------|------|
| Mini player workflow data dir | `$HOME/Library/Application Support/Alfred/Workflow Data/com.vdesabou.spotify.mini.player` | read-only |
| Authoritative library DB | `<data_dir>/library.db` | `SQLite3::OPEN_READONLY` |
| Mini player install dir | `$HOME/Library/Application Support/Alfred/Alfred.alfredpreferences/workflows/user.workflow.<UUID>` | read-only fallback only |
| Mini player prefs plist | `<install_dir>/prefs.plist` | read-only fallback only |

Notes:
- The per-user DB at `<data_dir>/users/<userid>/library.db` exists on some
  installs but was **empty** during investigation. Do **not** rely on it. The
  top-level `library.db` is authoritative.
- The install dir UUID is generated by Alfred at install time and varies per
  machine. Path discovery uses Alfred's AppleScript API (`tell application id
  "com.runningwithcrayons.Alfred" to ...`), which abstracts over the UUID. The
  PlistBuddy fallback discovers the UUID by globbing
  `user.workflow.*/info.plist` for `bundleid =
  com.vdesabou.spotify.mini.player`.

## 2. Credential storage

The mini player persists OAuth credentials as **plaintext** keys in its
`prefs.plist`, written via Alfred's per-workflow configuration API. The four
keys this companion reads:

| Key | Required | Used for |
|-----|----------|----------|
| `__oauth_client_id` | yes | Basic auth on token refresh |
| `__oauth_client_secret` | yes | Basic auth on token refresh |
| `__oauth_refresh_token` | yes | Exchange for access token |
| `__userid` | no (optional) | Skip `GET /v1/me` when creating Nuked playlist |

`__oauth_access_token` is also persisted by the mini player, but is ignored
here — we always perform our own refresh to guarantee a fresh ~1h token.

**No encryption.** If a future mini player release adds encryption, refresh
calls will fail with `invalid_grant` and the companion surfaces a clear error
pointing back to this doc.

Read path (primary):

```sh
osascript -e 'tell application id "com.runningwithcrayons.Alfred" to \
  return value of configuration "__oauth_refresh_token" in workflow \
  "com.vdesabou.spotify.mini.player"'
```

Read path (fallback, used when Alfred is not running):

```sh
/usr/libexec/PlistBuddy -c 'Print :__oauth_refresh_token' \
  "<install_dir>/prefs.plist"
```

Source of truth in mini player code: `functions.php` around line 7931
(`getSetting()`) and 8010 (the AppleScript writer in `setSetting()`). The
four `__oauth_*` key names are also referenced in `resetSettings()` around
line 8019.

## 3. Database schema

Only one table is read: `playlists` in the top-level `library.db`.

```sql
CREATE TABLE playlists (
  uri                    TEXT PRIMARY KEY NOT NULL,
  name                   TEXT,
  nb_tracks              INT,
  author                 TEXT,
  username               TEXT,
  playlist_artwork_path  TEXT,
  ownedbyuser            BOOLEAN,
  nb_playable_tracks     INT,
  duration_playlist      TEXT,
  nb_times_played        INT,
  collaborative          BOOLEAN,
  public                 BOOLEAN,
  name_deburr            TEXT
);
```

Columns this companion actually depends on:

- `uri` — full `spotify:playlist:<id>` URI.
- `name` — used for case-insensitive "Nuked" lookup.
- `ownedbyuser` — filter to playlists the user can modify.
- `nb_tracks` — only used as a tiebreaker if multiple "Nuked" playlists exist.

Tables explicitly **not** touched: `tracks`, `episodes`, `shows`,
`followed_artists`, `counters`, any per-user table.

## 4. Bundle identifiers

| Bundle id | Owner | Why we care |
|-----------|-------|-------------|
| `com.runningwithcrayons.Alfred` | Alfred app | Target of `tell application id` for configuration read |
| `com.vdesabou.spotify.mini.player` | Mini player workflow | Identifies which workflow's config we read |

If Alfred ever ships a new bundle id, the AppleScript primary read path
breaks; the PlistBuddy fallback still works.

## 5. Behavioural assumptions

These are not *file-level* coupling points but they are still coupling:

1. The mini player refreshes `library.db` roughly hourly. Stale playlists are
   tolerated: at worst the current invocation misses one playlist; the next
   invocation catches it.
2. Spotify's `DELETE /v1/playlists/{id}/tracks` is **idempotent** — returns
   200 even if the track is not in the playlist. We rely on this to avoid an
   extra `GET /v1/playlists/{id}/tracks` per playlist. If this ever changes,
   add a pre-check or accept benign "track not found" errors per-playlist.
3. Spotify refresh tokens do not invalidate on use (they occasionally rotate;
   the previous token has a grace period). Concurrent use by the companion
   and the mini player is safe.

## 6. Upgrade checklist for the maintainer

When the mini player ships a new release, before users adopt it:

- [ ] Diff `functions.php` `getSetting()` / `setSetting()` / `resetSettings()`
      against your last-known-good version. The four `__oauth_*` key names
      must be unchanged.
- [ ] Confirm `prefs.plist` still contains plaintext `__oauth_*` values
      (`PlistBuddy -c Print` on a test install). If encrypted, the companion
      will need an OAuth path of its own.
- [ ] Confirm `library.db` still lives at
      `$HOME/Library/Application Support/Alfred/Workflow Data/com.vdesabou.spotify.mini.player/library.db`.
- [ ] Run the schema query
      `sqlite3 library.db ".schema playlists"` and confirm `uri`, `name`,
      `ownedbyuser` columns still exist. Other column changes don't matter.
- [ ] Confirm Alfred's bundle id and the mini player's bundle id are
      unchanged (rename = breaking change).
- [ ] Run `docs/smoke-test.md` against a non-critical Spotify account.
